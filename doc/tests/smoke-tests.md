# Smoke-тести

**Проєкт:** Веб-сайт для персонального фінансового обліку
**Версія документа:** 1.0
**Дата:** 21.10.2026

---

## 1. Призначення

Smoke-набір — мінімальна перевірка того, що розгорнута збірка працює: сайт доступний, база даних підключена, користувач може увійти, внести операцію і побачити баланс та графіки. Набір виконується **після кожного деплою** на staging і production і займає не більше 3 хвилин автоматично або 15 хвилин вручну.

Правила:

- набір проходиться повністю, порядок перевірок фіксований;
- **будь-яке падіння** означає, що збірка не приймається в тестування (staging) або виконується rollback (production, NFR-16);
- на production використовується службовий акаунт `smoke@<домен>`, нові акаунти не створюються (SMK-03 пропускається), створені операції видаляються в кінці прогону.

## 2. Автоматизований запуск

Набір автоматизований у `tests/e2e/smoke.spec.ts` (тег `@smoke`), назви тестів збігаються з ID перевірок.

```bash
# staging
BASE_URL=https://<staging-домен> npm run test:smoke

# production — службовий акаунт, SMK-03 пропускається
BASE_URL=https://<домен> SMOKE_EMAIL=smoke@<домен> SMOKE_PASSWORD=*** npm run test:smoke -- --project=chromium
```

У CI набір запускається job-ом після деплою (`.github/workflows/deploy.yml`); звіт Playwright і trace падінь зберігаються як артефакти.

**Прибирання (production):** видалити всі операції з коментарем `smoke`, створені під час прогону; баланс службового акаунта повертається до початкового значення. В автоматичному режимі це робить фікстура `marker` з `tests/e2e/support.ts`.
