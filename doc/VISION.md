# Vision документ

**Проєкт:** Веб-сайт для персонального фінансового обліку
**Версія документа:** 1.0
**Дата:** 20.09.2026

---

## 1. Опис продукту

Веб-сайт для персонального фінансового обліку забезпечує користувачам можливість вносити інформацію про свої прибутки та видатки, оцінювати свій поточний фінансовий стан і відстежувати його динаміку в часі.

---

## 2. Проблема, яку вирішує проєкт

Більшість людей не веде систематичного обліку власних фінансів. Інформація про доходи та витрати розпорошена між банківськими застосунками, готівковими розрахунками, паперовими нотатками чи таблицями Excel. Через це:

- людина не знає точно, скільки грошей у неї є на поточний момент з урахуванням усіх джерел;
- неможливо швидко визначити, на що саме витрачається найбільша частка коштів;
- важко помітити зростання витрат до того, як це стане проблемою;
- таблиці Excel потребують ручних формул і не дають наочної картини без додаткових зусиль;
- банківські застосунки показують лише операції конкретного банку і не враховують готівку та інші рахунки.

**Суть проблеми:** відсутність простого, єдиного та наочного інструменту, який дозволяє вручну фіксувати всі фінансові операції та одразу бачити поточний стан і динаміку особистих фінансів.

## 3. Цілі, очікування та критерії прийняття

### 3.1. Цілі проєкту

| №   | Ціль                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------- |
| 1   | Надати користувачу можливість швидко вносити доходи та витрати з категорією, сумою, датою та коментарем |
| 2   | Автоматично розраховувати поточний баланс користувача                                                   |
| 3   | Наочно відображати структуру витрат і доходів за категоріями                                            |
| 4   | Показувати динаміку фінансового стану за обраний період                                                 |

### 3.2. Очікування

- Користувач без спеціальної підготовки може почати роботу з сайтом протягом кількох хвилин після реєстрації.
- Внесення однієї операції займає не більше 30 секунд.
- Сайт коректно працює на комп'ютері, планшеті та смартфоні.
- Дані користувача зберігаються між сесіями та доступні лише йому.

### 3.3. Критерії прийняття (Acceptance criteria)

| №    | Функція                  | Критерій прийняття                                                                                                                                                                           |
| ---- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC1  | Реєстрація та вхід       | Користувач може зареєструватися за email і паролем, увійти та вийти з системи; неавторизований користувач не має доступу до сторінок обліку                                                  |
| AC2  | Додавання операції       | Користувач може додати дохід або витрату із полями: тип, сума (> 0), категорія, дата, коментар (необов'язковий); некоректні дані не зберігаються, користувач бачить повідомлення про помилку |
| AC3  | Редагування та видалення | Користувач може змінити або видалити будь-яку власну операцію; баланс і графіки оновлюються відповідно                                                                                       |
| AC4  | Категорії                | Доступний базовий набір категорій доходів і витрат; користувач може створювати, перейменовувати та видаляти власні категорії                                                                 |
| AC5  | Поточний баланс          | Баланс дорівнює сумі всіх доходів мінус сума всіх витрат і відображається на головній сторінці                                                                                               |
| AC6  | Список операцій          | Операції відображаються списком, відсортованим за датою; доступна фільтрація за періодом, типом і категорією                                                                                 |
| AC7  | Структура витрат         | Для обраного періоду відображається кругова діаграма витрат за категоріями з відсотками                                                                                                      |
| AC8  | Динаміка                 | Для обраного періоду відображається графік доходів, витрат і балансу по місяцях                                                                                                              |
| AC9  | Ізоляція даних           | Користувач бачить і може змінювати лише власні дані                                                                                                                                          |
| AC10 | Адаптивність             | Усі сторінки коректно відображаються на екранах шириною від 360 px                                                                                                                           |
| AC11 | Продуктивність           | Будь-яка сторінка завантажується не довше ніж за 2 секунди                                                                                                                                   |

## 4. Цільова аудиторія, зацікавлені особи та обмеження

### 4.1. Цільова аудиторія

| Група                              | Опис                                                             | Потреби                                                     |
| ---------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------- |
| Студенти                           | Мають обмежений бюджет (стипендія, підробіток, допомога батьків) | Контролювати щомісячні витрати, не виходити за межі бюджету |
| Працюючі молоді люди (20–35 років) | Мають регулярний дохід і різноманітні витрати                    | Розуміти, куди йдуть гроші, планувати заощадження           |
| Сім'ї                              | Спільний бюджет із кількома джерелами доходу                     | Бачити загальну картину доходів і витрат                    |
| Фрилансери та самозайняті          | Нерегулярні доходи з різних джерел                               | Відстежувати динаміку доходів по місяцях                    |

### 4.2. Зацікавлені особи (Stakeholders)

| Стейкхолдер         | Роль                                | Інтерес                                                  |
| ------------------- | ----------------------------------- | -------------------------------------------------------- |
| Кінцеві користувачі | Використовують сайт                 | Зручний, швидкий і безпечний облік фінансів              |
| Розробник           | Проєктує, розробляє, тестує продукт | Чіткі вимоги, реалістичні терміни                        |
| Викладач / замовник | Оцінює результат                    | Відповідність вимогам, якість документації та реалізації |

### 4.3. Обмеження

**Технічні:**

- веб-застосунок, що працює в сучасних браузерах (Chrome, Firefox, Edge, Safari — останні дві версії);
- дані вносяться вручну, інтеграція з банками не передбачена;
- одна валюта для всіх операцій користувача (гривня).

**Поза межами проєкту (out of scope):**

- мобільний застосунок;
- автоматичний імпорт банківських виписок;
- мультивалютність;
- спільні (сімейні) акаунти;
- інвестиційний облік.
