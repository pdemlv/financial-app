# Специфікація вимог до програмного забезпечення (SRS)

**Проєкт:** Веб-сайт для персонального фінансового обліку
**Версія документа:** 1.0

---

## 1. Вступ

### 1.1. Призначення документа

Документ описує функціональні та нефункціональні вимоги до веб-сайту для персонального фінансового обліку. Він є основою для проєктування архітектури, розробки інтерфейсу, написання тест-кейсів і перевірки готовності продукту до релізу.

### 1.2. Обсяг продукту

Система дозволяє зареєстрованому користувачу вручну вносити доходи та витрати, зберігати їх у власному обліковому записі, бачити поточний баланс, структуру витрат за категоріями та динаміку фінансового стану в часі.

Поза межами системи: мобільний застосунок, автоматичний імпорт банківських виписок, мультивалютність, спільні акаунти, інвестиційний облік.

### 1.3. Терміни та скорочення

| Термін    | Значення                                                          |
| --------- | ----------------------------------------------------------------- |
| Операція  | Запис про дохід або витрату: тип, сума, категорія, дата, коментар |
| Баланс    | Сума всіх доходів мінус сума всіх витрат користувача              |
| Категорія | Назва групи операцій (наприклад, «Продукти», «Зарплата»)          |
| Період    | Проміжок часу, за який будуються підсумки та графіки              |
| FR        | Функціональна вимога (Functional Requirement)                     |
| NFR       | Нефункціональна вимога (Non-functional Requirement)               |
| AC        | Критерій прийняття з Vision документа (Acceptance Criteria)       |

### 1.5. Пріоритети вимог

Застосовується модель MoSCoW:

- **M (Must)** — без цієї вимоги продукт не виконує свого призначення, реалізується обов'язково;
- **S (Should)** — важлива вимога, реалізується після всіх Must;
- **C (Could)** — бажана вимога, реалізується за наявності часу.

## 2. Загальний опис

### 2.1. Перспектива продукту

Самостійний веб-застосунок із клієнтською частиною в браузері, серверним API та реляційною базою даних. Зовнішні інтеграції відсутні: усі дані вносить користувач.

### 2.2. Користувачі системи (актори)

| Актор         | Опис                                                 | Рівень доступу                                                            |
| ------------- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| Гість         | Відвідувач, який не увійшов у систему                | Головна сторінка-презентація, реєстрація, вхід                            |
| Користувач    | Зареєстрована особа, яка веде облік власних фінансів | Повний доступ до власних операцій, категорій та аналітики                 |
| Адміністратор | Особа, яка підтримує працездатність системи          | Технічний доступ: health-check, логи, керування базовим набором категорій |

### 2.3. Припущення та залежності

- Користувач має постійний доступ до інтернету та сучасний браузер.
- Усі суми вводяться в гривнях.
- Користувач вносить операції самостійно і відповідає за їх достовірність.
- Доступність системи залежить від хостингу застосунку та бази даних.
