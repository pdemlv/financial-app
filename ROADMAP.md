## 1. План реалізації

### 1.1. Підхід до розробки

Артефакти вимог, дизайну, тестування і розгортання створюються паралельно з кодом і потрапляють у репозиторій до відповідної контрольної дати. Пріоритет — спочатку функції, без яких продукт не має сенсу (облік операцій і баланс), потім аналітика.

### 1.2. Технологічний стек

| Шар                            | Технологія                                  |
| ------------------------------ | ------------------------------------------- |
| Клієнтська частина             | React, Next.js                              |
| Серверна частина               | Next.js API Routes (Node.js)                |
| База даних                     | PostgreSQL                                  |
| Доступ до БД                   | Prisma ORM                                  |
| Автентифікація                 | NextAuth (email + пароль, хешування bcrypt) |
| Графіки                        | Recharts                                    |
| Контроль версій                | Git, GitHub                                 |
| Модульні та інтеграційні тести | Jest, React Testing Library                 |
| API / UI тести                 | Supertest, Playwright                       |
| CI/CD                          | GitHub Actions                              |
| Розгортання                    | Vercel (застосунок), Neon (PostgreSQL)      |

### 1.3. Порядок робіт

1. **Ініціація** — формулювання бачення, планування, створення репозиторію.
2. **Вимоги** — функціональні та нефункціональні вимоги, Use Case Diagram, SRS / backlog з User Stories.
3. **Дизайн і прототип** — загальна архітектура системи, модель даних, дизайн інтерфейсу, специфікація дизайну і зразки UI.
4. **Базова інфраструктура і CI** — каркас застосунку, БД, реєстрація/вхід, перший pipeline у GitHub Actions.
5. **Облік операцій** — CRUD доходів і витрат, категорії, список із фільтрами.
6. **Аналітика** — поточний баланс, структура витрат, динаміка.
7. **Тестування** — ручні тести, набір smoke-тестів, автоматизовані тести, тест-план.
8. **Розгортання та інтеграція** — розширення CI до CI/CD, опис середовищ і стратегії розгортання, моніторинг і повернення до стабільної версії.

### 2.5. Ризики та способи їх уникнення (Risks mitigation)

| №   | Ризик                                                                                 | Ймовірність | Вплив    | Способи уникнення / зменшення                                                                                     |
| --- | ------------------------------------------------------------------------------------- | ----------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| R1  | Зрив стислого терміну через недооцінку обсягу робіт                                   | Висока      | Високий  | Щоденна перевірка прогресу; функції поділені на обов'язкові та бажані; бажані реалізуються лише за наявності часу |
| R2  | Помилки в розрахунку балансу та сум                                                   | Середня     | Високий  | Зберігання сум у копійках (цілі числа); модульні тести для функцій розрахунку в CI                                |
| R3  | Незручний інтерфейс для користувачів                                                  | Середня     | Середній | Макети і специфікація дизайну на етапі M2; коротке тестування з 3–5 потенційними користувачами перед релізом      |
| R4  | Документація (SRS, тест-план, план розгортання) пишеться в останній день перед здачею | Висока      | Високий  | Документи створюються паралельно з розробкою і мають власні дедлайни в таблиці артефактів                         |
| R5  | Тестування не встигає через пізній старт розробки                                     | Висока      | Високий  | Тест-кейси пишуться на основі критеріїв прийняття ще до готовності функції; smoke-набір автоматизується першим    |
| R6  | Нестабільний або «червоний» CI blocks команду                                         | Середня     | Середній | Заборона мерджу в `main` при невдалому pipeline; швидкі тести (< 5 хв) у CI, довгі e2e — окремим job              |
